# E1c «выбор памяти моделью» — результат (пре-регистрация v1.1)

**Итог.**
- Главная гипотеза не подтверждена: выбор памяти моделью (V7) не лучше авто-раскрытия гибрида (V6) по «выводу». По направлению V7 даже хуже: 12 % против 18 %, p = 0,081.
- Защита по «выдумке» тоже не выполнена: у V7 выдумок больше на 11 п.п.
- Стоп-правило для графа не выполнено: V6 не даёт +8 п.п. к RAG (V2) ни на «связать», ни на «менялось».
- Память в целом помогает против варианта без памяти (V6 и V2 лучше V1), а гибрид V6 сильнее RAG только на «вспомнить».

## Как прогоняли

- **Модель:** Nemotron-3 Ultra (NVIDIA), рассуждения выключены. Контекст 6600 токенов, память ≤ 600 токенов.
- **Вопросы:**
  - основной слой — 200 новых вопросов (4 проекта × 50);
  - вторичный слой — 54 вопроса E1b;
  - 4 варианта (V1, V2, V6, V7) — всего 1016 ответов.
- **Судьи:**
  - основной — DeepSeek V4.1 Flash, рубрика e1c.2 со строгим «выводом» и обязательными условиями по типам; 800/800 вердиктов, 451,24 ₽ по учёту;
  - второй — gpt-oss-20b на детерминированных 20 % (140 ответов);
  - старый слой — gpt-oss, 216/216;
  - мягкая рубрика e1b.3 — на тех же 20 % (поправка v1.1).
- **«Выдумка»** — слепая ручная проверка с полным диалогом загрузки, отдельными сессиями Claude. Проверены все 538 ответов, отмеченных хоть одним судьёй; подтверждено 378.

## Разведка (не предрегистрировано; `reports/e1c/main_final/explore.md`)

- **«Связать»: ломается извлечение.**
  - В памяти V6 полным фрагментом было 23 % нужных опорных фактов, у V2 — 16 %. Ни в одном из 60 вопросов в памяти не было всех нужных фактов.
  - Из фактов, попавших в память, модель учла 84 % (V6) и 76 % (V2).
  - Довод за раздельный поиск по темам (V9).
- **«Менялось»: ошибки V6.**
  - Лишь 7 из 49 ошибок — «устаревшая реплика была в памяти и повторена»; у V2 таких 3 из 43.
  - Чаще устаревшее повторяется без него в памяти: 12 и 11 случаев. Вероятно, из резюме или окна.
  - Пометка «позже заменено» стояла только на 4 из 21 устаревших реплик в памяти V6: детектор ловит мало смен.

## Ограничения

- **Недетерминизм при перезапусках.** Прогон перезапускался из кэша несколько раз. При равных весах сущностей порядок зависел от `PYTHONHASHSEED`, поэтому часть блоков памяти и ответов при перезапуске пересчитывалась.
  - Итоговые файлы каждого проекта — из одного полного прохода; последний проход шёл с `PYTHONHASHSEED=0`.
  - Исправление в коде (вторичный ключ сортировки) — после E1c.
- **«Выдумку» размечали сессии Claude:** вслепую, но той же модели, что строила систему.
- **Высокий уровень выдумок даже после ручной проверки** (38–60 %): Nemotron пишет длинные ответы и достраивает конкретику проекта (имена файлов, конфиги, «уже настроено»).
- **Обрывы ответов:** V1 — 14 % (ответы длиннее, без памяти), V2/V6/V7 — 2 %.
- **Мощность:** для +10 п.п. ≈ 0,8–0,9. Неподтверждение главной гипотезы при разнице −6 п.п. не в её пользу — это не «недобор мощности».
