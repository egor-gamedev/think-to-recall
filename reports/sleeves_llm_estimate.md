# Рукава из шагов мышления (планировщик): оценка числа вызовов LLM

Это оценка для этапа после IMLogic и ImplexConv. Ничего не запускалось.

## Что вызывает LLM

Планировщик раскладывает вопрос на шаги. Каждый шаг — отдельный поисковый запрос («рукав»), а найденное по шагам объединяется с поиском по самому вопросу. Метрика остаётся прежней — полнота поиска (Recall@k). **Ответов и судьи нет**: LLM нужна только для шагов.

Два способа (оба заимствованы):

| способ | вызовов на вопрос | что делает |
|---|---|---|
| **Self-Ask: один вызов** | 1 | из вопроса — 2–4 подвопроса за один раз |
| **IRCoT: итеративно** | ≤ 3 (в среднем ≈ 2,5) | шаг рассуждения → поиск → следующий шаг с найденным; до 3 шагов |

Объём одного вызова: на входе ≈ 300–600 токенов (вопрос плюс у IRCoT найденные записи), на выходе ≈ 100–200.

| ImplexConv dev (10 примеров) | 45 | 45 | ≤ 135 |

| Отладка (часть dev) | 50 + 20 | 70 | ≤ 210 |

Всё это больше лимита в 300 вызовов, поэтому нужно твоё отдельное «да» на каждую часть.

## Предложение

1. **Модель** — бесплатный NVIDIA API: Nemotron-3 Ultra или Mistral Large 4.
   - Подписку Z.ai не используем.
   - На timeweb осталось около 114 ₽ — только на крайний случай.
   - Ответы кэшировать по хэшу запроса, чтобы повторный прогон не тратил вызовы.
2. **Порядок:**
   - отладка: 70 вызовов на dev, сначала Self-Ask;
   - затем пре-регистрация;
   - затем основной прогон Self-Ask: 2 786 вызовов, при ≈ 1–2 с на вызов это примерно 1–1,5 часа;
   - IRCoT — только если Self-Ask покажет сигнал.
3. **Варианты сравнения:**
   - лучший вариант без LLM из IMLogic и ImplexConv;
   - он же плюс рукава;
   - dense + переранжирование плюс рукава — чтобы отделить вклад рукавов от вклада графа.
