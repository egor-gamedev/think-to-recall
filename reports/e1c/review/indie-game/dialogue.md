**[S1.1] Ассистент:**

Начать стоит со структуры папок — в Godot её потом больно менять, потому что пути зашиты в сцены (хотя редактор и умеет обновлять зависимости при перемещении через FileSystem dock — двигайте файлы только оттуда, не из проводника).

Вариант, который хорошо живёт в небольших проектах — «по фичам», а не «по типам файлов»:

```
res://
  autoload/          # синглтоны: GameState, SaveManager, Audio
  actors/
    player/          # player.tscn, player.gd, анимации
    npc/
  world/
    lighthouse/      # комнаты маяка
    island/
  puzzles/           # механизмы: шестерни, клапаны, линзы
  ui/
  assets/
    fonts/
    sfx/
    music/
  localization/
```

Скрипт лежит рядом со сценой, которой он принадлежит: `actors/player/player.gd` рядом с `player.tscn`. Тогда при переносе фичи в другую папку она переезжает целиком.

Ещё два правила, которые экономят нервы:

1. Имена файлов — `snake_case`, имена классов (`class_name`) — `PascalCase`. Godot на Windows не различает регистр в путях, а на Linux различает, и сборка, которая работала у вас, может упасть на Linux-машине из-за `Player.tscn` vs `player.tscn`.
2. Всё, что должно жить между сценами (прогресс, настройки), — в автозагрузках, а не в статических переменных узлов.

Нормальный старт. Пара советов по GameState, пока он маленький:

```gdscript
# autoload/game_state.gd
extends Node

signal flag_changed(flag: StringName, value: bool)

var chapter: int = 1
var _flags: Dictionary = {}

func set_flag(flag: StringName, value: bool = true) -> void:
    if _flags.get(flag, false) == value:
        return
    _flags[flag] = value
    flag_changed.emit(flag, value)

func has_flag(flag: StringName) -> bool:
    return _flags.get(flag, false)

func to_dict() -> Dictionary:
    return {"chapter": chapter, "flags": _flags.duplicate()}

func from_dict(d: Dictionary) -> void:
    chapter = d.get("chapter", 1)
    _flags = d.get("flags", {})
```

Смысл: снаружи никто не лезет в словарь напрямую, все изменения идут через `set_flag`, а на сигнал `flag_changed` можно повесить, например, открытие двери, которая зависит от насоса. И сразу заложены `to_dict`/`from_dict` — сохранения потом будут просто сериализовать этот словарь, в каком бы формате вы их ни писали.

Флаги лучше называть `StringName` с префиксом главы: `&"ch1_pump_fixed"`. Когда флагов станет двести, префикс сильно помогает.

```gdscript
# actors/player/state.gd
class_name PlayerState
extends Node

var player: Player

func enter(_prev: StringName) -> void: pass
func exit() -> void: pass
func physics_update(_delta: float) -> StringName:
    return &""   # пустое имя = остаёмся в этом состоянии
```

```gdscript
# actors/player/state_machine.gd
extends Node

@export var initial: PlayerState
var current: PlayerState

func _ready() -> void:
    for s in get_children():
        s.player = owner
    current = initial
    current.enter(&"")

func _physics_process(delta: float) -> void:
    var next := current.physics_update(delta)
    if next != &"":
        var prev := current.name
        current.exit()
        current = get_node(NodePath(next))
        current.enter(prev)
```

Состояния: `Idle`, `Walk`, `Climb` (лестницы в маяке), `Interact` (когда крутим вентиль — игрок заблокирован), `Cutscene`. Каждое — 30–80 строк, и баг в лазании по лестнице ищется в одном файле, а не в 400 строках.

Переход на `Interact` удобно делать по сигналу от механизма, а не опросом: механизм говорит «меня начали крутить», игрок уходит в состояние и ждёт сигнала «закончили».

**[S1.7] Ассистент:**

Классическая история для пиксель-арта: игрок стоит на дробной координате (например, x = 103.4), камера сглаживается к другой дробной координате, и при отрисовке спрайт и фон округляются по-разному — получается дрожание на 1 пиксель.

Что проверить по порядку:

1. Project Settings → Rendering → 2D → **Snap 2D Transforms to Pixel** и **Snap 2D Vertices to Pixel** — включить.
2. Физику и камеру — в одном цикле. У Camera2D свойство `process_callback` поставьте в `Physics`, раз игрок двигается в `_physics_process`.
3. Если включено сглаживание — оно и есть главный источник дробных позиций. Попробуйте без него: в головоломке с маленькими комнатами жёсткая привязка часто выглядит даже лучше.
4. Физический тикрейт и частота монитора: если игра на 60 Гц физики, а монитор 144 Гц, будет микрорывок. Это лечится интерполяцией физики (`physics/common/physics_interpolation`) — проверьте, есть ли она для 2D в вашей версии, и включайте, только если первые пункты не помогли.

Хорошая связка: Deck — это по сути Linux, так что нативная Linux-сборка и Deck проверяют друг друга. Несколько практических вещей:

1. **Экспорт под Linux** в 4.3 — пресет `Linux/X11` (он же работает и на Deck в режиме игры). Архитектура `x86_64`. Включите встраивание PCK в бинарник — меньше файлов, меньше шансов, что депо Steam соберётся без `.pck`.

3. **Требования Deck Verified**, которые чаще всего роняют проверку:
   - игра запускается и работает без клавиатуры и мыши;

   - стандартное разрешение 1280×800 (16:10) или 1280×720 поддерживается.
4. **Proton не нужен** — если есть нативная Linux-сборка, Steam запустит её. Но на всякий случай проверьте и Windows-сборку через Proton: часть игроков на Deck принудительно включает Proton, и баги там другие.

**[S1.15] Ассистент:**

В Godot это делается просто: CSV импортируется как набор переводов.

Формат файла `localization/strings.csv`:

```csv
keys,ru,en
MENU_NEW_GAME,Новая игра,New game
MENU_CONTINUE,Продолжить,Continue
HINT_INTERACT,"Нажмите {button}, чтобы осмотреть","Press {button} to inspect"
CH1_PUMP_BROKEN,"Насос молчит. Похоже, сорвало шток.","The pump is silent. Looks like the rod snapped."
```

Первая колонка — ключ, дальше по колонке на локаль. Ячейки с запятыми — в кавычках.

После сохранения Godot сам импортирует файл и создаст `strings.ru.translation` и `strings.en.translation`. Их нужно добавить в Project Settings → Localization → Translations.

В коде:

```gdscript
label.text = tr("CH1_PUMP_BROKEN")
hint.text = tr("HINT_INTERACT").format({"button": InputGlyphs.for_action("interact")})
```

А узлы `Label`/`Button` с текстом-ключом в свойстве `text` переводятся автоматически (auto translate включён по умолчанию).

Смена языка:

```gdscript
TranslationServer.set_locale("en")
```

Пара советов на будущее:

- Ключи — по смыслу, а не по тексту (`CH1_PUMP_BROKEN`, а не `NASOS_MOLCHIT`), тогда правка русской фразы не ломает ключ.
- Оставляйте плейсхолдеры `{button}`, а не склейку строк: в другом языке порядок слов может быть другим.
- Длину строк держите в голове с самого начала — при маленьком базовом разрешении каждый символ на счету, а русский обычно на 15–25 % длиннее английского, так что верстайте окна под русский.

func save_game(room: String) -> void:

    data["room"] = room
    var f := FileAccess.open(PATH, FileAccess.WRITE)

        push_error("save failed: %s" % FileAccess.get_open_error())
        return

    GameState.from_dict(data)
    return data

Файл `.tres` — это не просто данные, а описание ресурса, и в нём может быть встроенный `GDScript` (подресурс с `script/source`). `ResourceLoader.load()` такой файл честно загрузит, а скрипт выполнится при создании объекта. 3. **Проверка `.tres` перед загрузкой** (искать `script` в тексте) — ненадёжно, легко обойти.

Для вашей ситуации — первый вариант. Главное — не передавать `true` в `get_var` и не хранить в сейве объекты.

    runs-on: ubuntu-22.04

      - uses: actions/download-artifact@v4

          releaseBranch: beta

**[S6.11] Ассистент:**

Известное поведение на Linux: после сна аудиоустройство переинициализируется, а Godot продолжает писать в старое. Обходной путь — ловить возврат фокуса и перезапускать вывод:

```gdscript
func _notification(what: int) -> void:
    if what == NOTIFICATION_APPLICATION_FOCUS_IN:
        var dev := AudioServer.output_device
        AudioServer.output_device = "Default"
        AudioServer.output_device = dev
```

Переключение устройства туда-обратно заставляет драйвер переоткрыть поток. Проверьте на Deck: усыпить, разбудить, пройти комнату с эмбиентом.

**[S6.12] Пользователь:**

Помогло, звук возвращается. На этом закрываю неделю.
