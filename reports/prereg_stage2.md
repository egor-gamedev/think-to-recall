## 1. Гипотеза

Решающий факт далёк от вопроса, но близок к **шагу рассуждения** (например, «грыжа диска» — к шагу «здоровье и ограничения пользователя»).

**Главная гипотеза:** поиск по всему тексту шагов плана, слитый с базой (SC), находит решающий факт лучше базы A.

**Вторичные:**
- деление шагов на рукава (SR) добавляет что-то к поиску по всему тексту шагов (SC). Ожидание по dev — около нуля;
- SR лучше базы A.

Граф поверх рукавов (SG) — вариант, только описательно. D0-варианты — после сброса квоты GPU.

**Гипотеза изменена до заморозки, по итогам dev и открыто** (решение Егора, 2026-11-08). Было: главное — SR против SC (вклад деления на рукава). На dev деление на рукава не дало прироста над поиском по всему шагу (§6), поэтому главным стало сравнение SC с базой.

## 2. Планировщик

- **Один вызов LLM на вопрос, не больше 3 шагов.** Шаг — короткий поисковый запрос о прошлом факте пользователя: цель, ограничение, предпочтение, план, состояние, решение.
- **Промпт** — `scripts/planner.py::PROMPT`, без примеров из данных.
- **Модель:** бесплатный NVIDIA API, `mistralai/mistral-large-4-1t-a52b`, температура 0, `max_tokens` = 3000. Модель сначала «думает» скрытым текстом: при лимите 300 токенов все 20 ответов дым-теста были пустыми.
- **Кэш** — по хэшу запроса: повторный прогон вызовов не делает.
- **Неразобранный ответ** означает «шагов нет»: у такого вопроса SR = SC = SG = база. Долю таких ответов указываем. На dev — 1 из 330.

## 3. Варианты (все — поверх базы; RRF k = 60)

| | вариант | что это |
|---|---|---|
| S0 | база | выдача базы по вопросу |
| **SR** | **рукава** | RRF(база, выдача базы по шагу 1, …, по шагу n) — по поиску на шаг |
| **SC** | **контроль: шаги одним поиском** | RRF(база, выдача базы по склеенному тексту всех шагов). Шаги те же, слияние то же; разница с SR только в том, что поиск один, а не по шагу |
| SG | рукава + граф (вариант) | база + **старый** шлюз этапа 1 (без проверки переранжировщиком). К стартам добавлены понятия шагов и первый результат базы по каждому шагу. Правила прежние: пересечение ≥ 2 стартов, запас PPR × 4, не больше 2 вытеснений, только добавить или поднять |

**База главного сравнения — A (dense e5) на обоих наборах** (решение Егора, 2026-11-08): квота GPU Kaggle исчерпана до сброса, а варианты поверх A считаются без GPU-моделей Qwen.

**D0-варианты — вторичные, после сброса квоты:** только IMLogic, где D0 — сильнейшая база (11,6 против 6,0 у A). На ImplexConv D0 не считается: там база A сильнее (16,3 против 11,7).

## 4. Сравнения (Recall@5 по эталону: `memory_l` / сессии-доказательства)

Тест тот же, что в bench1b и на этапе 1: односторонний парный перестановочный со сменой знака, 10 000 перестановок, seed 0; 95 % бутстреп; победы и поражения.

| | сравнение | роль | поправка |
|---|---|---|---|
| **H1** | **SC − A** | главное: поиск по всему тексту шагов лучше базы | Холм на 2 (два набора) |
| H2 | SR − SC | вторичное: вклад деления на рукава; ожидание по dev ≈ 0 | Холм на 4 (H2 и H3 × два набора) |
| H3 | SR − A | вторичное: рукава лучше базы | там же |
| — | SG − A, SG − SR | описательно | — |
| — | S0 / SR / SC / SG поверх D0, только IMLogic | вторичное, после сброса квоты GPU; Холм отдельно, на 3 сравнения (SC − D0, SR − SC, SR − D0) | — |

Все сравнения — поверх A; S0 = A.

**Критерий:**
- **Поиск по шагам плана полезен:** H1 значим хотя бы на одном наборе, **и** на другом наборе обратный тест (A > SC) не значим (p > 0,05 без поправки).
- **Не хуже:** если H1 нигде не значим, но обратный тест тоже нигде не значим — «прироста нет», без вывода «работает».
- **Вредит:** обратный тест значим хотя бы на одном наборе.
- **Деление на рукава (H2):** вывод «рукава полезны» — только если H2 значим. Иначе в отчёте: «деление на рукава не дало прироста над поиском по всему тексту шагов».
- **Граф (SG)** — только описательно; в продукт по этим данным не включается.

## 7. Неудачный подход: шлюз с проверкой переранжировщиком (rrgate) — записано как вывод

Проверялось на dev (ядро `ctxgraph-stage2-rrgate`, пересчёт `scripts/rrgate_sweep.py`; `reports/implicit/stage2_rrgate/`).

**Правило.** Кандидат графа вытесняет запись базы, только если оценка Qwen3-Reranker-4B (вероятность «да» относительно вопроса) у него не ниже, чем у вытесняемой, минус δ.

**Результат.**
- При δ ≤ 0 проверка блокирует **все** вставки графа на обоих наборах: D и SG совпадают с D0.
- При δ = 1 проверка не срабатывает никогда, это старый шлюз.
- При промежуточных δ (0,05–0,5) проходят единицы кандидатов, устойчивого эффекта нет: на IMLogic D с новым шлюзом от 1 / 2 до 3 / 3.

**Причина — по построению.**
- Переранжировщик оценивает сходство с вопросом, а решающее воспоминание с вопросом непохоже.
- Записи на местах 4–5 выдачи D0 уже отобраны тем же переранжировщиком. Кандидат графа, которого переранжировщик оценил бы выше, обычно уже был бы в выдаче.
- Поэтому эта проверка не отделяет полезные вставки графа от вредных.

**Решение Егора:** δ не подбирается; rrgate в этап 2 не входит; SG — со старым шлюзом, как вариант.

Пересчёт сверен: при δ = 1 он воспроизводит D этапа 1 на dev (IMLogic 11,6, 4 / 4; ImplexConv 16,2, 4 / 3) и SG_D0 отладочного ядра (13,0, 12 / 8).

## Поправка 1 (2026-11-08, до просмотра любых выдач основной части; решение Егора)

**Причина.** Около 16:00 МСК бесплатный NVIDIA API для модели планировщика (`mistralai/mistral-large-4-1t-a52b`) почти перестал отвечать: запросы обрываются по таймауту 240 с. К 17:50 получено 446 из 2 786 ответов, все — по IMLogic. Модель и поставщик **не меняются**.

**Что меняется:**
1. **Порядок.** Сначала ImplexConv, потом остаток IMLogic.
   - Вопросы ImplexConv берутся в порядке `random.Random(0).shuffle` по отсортированным id всех 855 основных вопросов.
   - Это нужно, чтобы любой префикс содержал opposed и supportive в общей пропорции. В порядке загрузчика сначала идут все 255 opposed.
2. **Минимум для анализа:**
   - **ImplexConv** — первые **300** вопросов этого порядка; анализируется самый длинный непрерывный префикс с полученными ответами, но не короче 300.
   - **IMLogic** — только **пользователи целиком**: все вопросы пользователя получили ответ. Частично обработанные пользователи не входят.
   - Если до конца прогона получены все ответы, анализ идёт на всех 2 786 вопросах, как в §4.
3. **Неудавшийся запрос** (все повторы оборвались) — это не «шагов нет»: такой вопрос остаётся без ответа и в анализ не входит. «Шагов нет» — только у полученного, но неразобранного ответа (§2).
4. **Где считается.** Планировщик, поиск A / SC / SR / SG и анализ — в ядре Kaggle **на CPU** (без GPU и без моего компьютера):
   - ключ NVIDIA — из Kaggle Secrets;
   - ответы пишутся в выход ядра по мере получения;
   - при 12-часовом лимите работа продолжается следующим ядром с этого кэша.
   - Эмбеддинги e5 ImplexConv и граф IMLogic посчитаны локально на CPU (их идентичность проверена на dev) и переданы в ядро датасетом.
5. **SG на ImplexConv** отложен: граф на CPU строится слишком долго (вне гипотез, §4).
6. **Тесты и поправка Холма** — как в §4, на тех вопросах, что вошли в анализ. Число вопросов по каждому набору указывается.
