## 1. Лицензия, код, модели и API

**Лицензия и код:**
- **Apache 2.0** — разрешает коммерческое использование и производные работы. Код открыт: `github.com/EverMind-AI/EverMemOS`.
- Сейчас ссылка ведёт на переименованный проект **EverOS** (тоже Apache 2.0, с файлом NOTICE).
- **Версии различаются:**
  - нынешний EverOS — «local-first»: Markdown + SQLite + LanceDB, без MongoDB, Elasticsearch и Redis;
  - EverMemOS из статей — по сторонним зеркалам, MongoDB + Elasticsearch + Milvus + Redis (не проверено по первоисточнику).
  - Для сравнения с IMLogic нужна версия того времени — её коммит надо найти в истории репозитория.

**Модели в статье EverMemOS:**
- LLM — GPT-4.1-mini (или GPT-4o-mini) для всех операций памяти;
- эмбеддинги — Qwen3-Embedding-4B;
- переранжировщик — Qwen3-Reranker-4B.
- В IMLogic на уровне диалогов EverMemOS шёл на GPT-4o-mini, отвечала GPT-5.1, извлекалось 30 воспоминаний.

**API:**
- В EverOS LLM задаётся в `~/.everos/everos.toml`: `[llm] model = "openai/gpt-4.1-mini"`, `base_url = "https://openrouter.ai/api/v1"`. Это OpenAI-совместимый `base_url`.
- **Бесплатный NVIDIA** (`https://integrate.api.nvidia.com/v1`, тоже OpenAI-совместимый) подключается подменой `base_url` и `model`. Это не проверено. Риски:
  - нужен JSON-режим: часть конвейера ждёт строгий JSON, а у NVIDIA зависали DeepSeek, GLM и Gemma;
  - лимиты частоты запросов.
- Эмбеддинги и переранжировщик (Qwen3-4B) можно запускать локально на Kaggle GPU.

## 2. Устройство поиска и куда встраивается граф

**Конвейер EverMemOS** (по статье):
1. **Построение.** Диалог режется на эпизоды: LLM определяет границы по скользящему окну. Из каждого эпизода LLM извлекает **MemCell** — пересказ эпизода, атомарные факты и Foresight (сигналы с ограниченным сроком). MemCell группируются в **MemScene** по эмбеддингам, без LLM. Профиль пользователя обновляется через LLM.
2. **Поиск.** Гибрид dense + BM25 по атомарным фактам с RRF → переранжирование эпизодов → **агентная проверка достаточности**: один вызов LLM на раунд, переписывание запроса и второй раунд — в 31 % вопросов LoCoMo. По умолчанию N = 10 сцен и K = 10 эпизодов для ответа.

**Куда встаёт наш граф.** После шага «гибрид + переранжирование», до проверки достаточности.
- Узлы графа — атомарные факты или MemCell, которые EverMemOS уже построила. Мы строим по ним свой граф понятий, текст не меняем.
- Наш шлюз получает её ранжирование как базу и **только добавляет или поднимает** кандидатов при пересечении стартов. Это ровно наша схема (КШ), где база — выдача EverMemOS.
- Инвариант «нет сигнала — выдача EverMemOS один в один» сохраняется.
- Техническое место — адаптер поиска. У RootMem он подменяемый: «To use another memory system, replace `retrieve_memories`».

**RootMem** (код в `IMLogic/rootmem/`) — **не поиск, а слой «корневых воспоминаний»:**
- `build_rootmem.py` пакетами прогоняет записи памяти пользователя через LLM и получает набор `agent_skills` (область навыка, правила исполнения, область решений). В статье это GPT-4o.
- `use_rootmem.py` на каждый вопрос делает один JSON-вызов маршрутизатора, который выбирает навыки, и отдельный поиск в сервисе памяти через API в стиле MemOS.
  - Сервис должен вернуть `data.memory_detail_list[*].memory_value`.
  - Навыки и воспоминания делят общий бюджет top-30.
- **RootMem не меняет выдачу базовой системы — он добавляет к ней свои элементы.** Наш шлюз меняет само ранжирование. По смыслу это два дополняющих способа: можно проверить и граф + RootMem.
- **Кода интеграции с EverMemOS в репозитории нет.** Выложен только адаптер к API MemOS. Результаты «EverMemOS + RootMem» (50,41 %) воспроизводимы лишь по описанию.

## 3. Готовые выходы EverMemOS в IMLogic

**Нет.** В репозитории только исходные диалоги (`HaluMem-Medium.jsonl`), вопросы и код:
- генерация данных;
- оценка (функции извлечения и поиска — заглушки, которые возвращают пустые списки);
- RootMem.

Построенной памяти EverMemOS, MemOS или Mem0 и ответов моделей нет. Значит, память EverMemOS для 20 диалогов придётся строить самим — или попросить у авторов в том же письме: в черновик можно добавить вопрос про выходы базовых систем.

## 5. Важно: memory-level IMLogic уже частично отвечает на вопрос «граф как надстройка»

В режиме memory-level граф строится **поверх готовых записей памяти** HaluMem — это `memory_points`, атомарные воспоминания, которые извлёк конвейер HaluMem. Это ровно та схема, которая нужна для надстройки:
- есть готовая память (здесь от HaluMem, там от EverMemOS);
- поверх неё наш граф понятий;
- шлюз меняет выдачу базового поиска только при сигнале.

Отличие одно: базовый поиск здесь наш (dense и dense + переранжирование), а не поиск EverMemOS с проверкой достаточности.

Поэтому в отчёте по IMLogic этот результат выделю отдельно: «граф как надстройка над готовой памятью, база — наш поиск». Прогон поверх самой EverMemOS ответит только на остаток вопроса: помогает ли граф поверх их поиска.

**Ограничение по dev.** Пользователи 12 и 13, 285 вопросов: граф в нынешнем виде `memory_l` не поднимает (2 победы / 3 поражения). Причина — ошибка извлечения понятий: имя пользователя срастается с понятиями в притяжательных группах. Подробности — в `reports/prereg_imlogic.md`, §5–6.
