**Нет, дефлировать зависимую переменную (долю в %) не нужно.**

1. **Математика:** `tax_effort = (Tax_nom / GRP_nom) × 100%`. Дефлятор сокращается в числителе и знаменателе.
2. **Экономический смысл:** Это уже *реальная* доля (реальные налоги / реальный ВРП). Инфляция убрана автоматически.

**В коде (`01_build_panel.R`):**

# Зависимая — БЕЗ дефлятора

## L09 · indie-game Q38

**Вопрос:** Проверь, что закрытый плейтест можно заливать из CI так же, как основную игру.

**Опорные факты:** I14: Закрытый плейтест через Steam Playtest, лимит 200 человек.; I22: Репозиторий на GitHub с Git LFS; CI в GitHub Actions экспортирует сборки и заливает их через steamcmd в ветку beta.; I19: Нынешняя сборка без запущенного Steam работать не будет.

**Эталон:** Steam Playtest — отдельное приложение со своим App ID и депо: в CI нужен отдельный скрипт steamcmd; сборке для плейтеста нужен его App ID при steamInitEx, иначе она закроется на старте.

**Ответ V6:**

Да, **технически идентично**. Разница только в `app_build_<PlaytestAppID>.vdf` и таргете деплоя.

### 1. Отдельный VDF для плейтеста
Создай `steamworks/app_build_playtest.vdf` (AppID = твой Playtest AppID, обычно `1234570` если игра `1234560`):
```vdf
"appbuild"
{
    "appid"     "1234570"          // Playtest AppID
    "desc"      "Playtest build %{GITHUB_RUN_NUMBER}"
    "buildoutput" "../export/playtest/"
    "depots"
    {
        "1234571"   // Depot ID для Playtest (обычно AppID+1)
        {
            "FileMapping"
            {
                "LocalPath" "*"
                "DepotPath" "."
            }
        }
    }
}
```
> **Depot ID** смотри в Steamworks → Playtest → Depots. Обычно он **не совпадает** с депо основной игры.

### 2. GitHub Actions — второй джоб / matrix
```yaml
# .github/workflows/steam_deploy.yml
jobs:
  deploy:
    strategy:
      matrix:
        target: [default, playtest]
        include:
          - target: default
            app_id: 1234560
            vdf: steamworks/app_build_default.vdf
            branch: "public"          # или "beta"
          - target: playtest
            app_id: 1234570
            vdf: steamworks/app_build_playtest.vdf
            branch: "playtest"        # фиксированная ветка у Playtest
    steps:
      - uses: actions/checkout@v4
        with: { lfs: true }
      - name: Export Godot
        uses: firebelley/godot-export@v6
        with:
          godot_version: 4.3
          export_name: "Windows/Linux/macOS"
          export_path: ../export/${{ matrix.target }}/
      - name: SteamCMD deploy
        run: |
          steamcmd +login ${{ secrets.STEAM_USER }} ${{ secrets.STEAM_PASS }} \
            +run_app_build ${{ matrix.vdf }} \
            +set_build_branch ${{ matrix.branch }} ${{ matrix.app_id }} \
            +quit
```
- `branch: "playtest"` — **обязательно**, у Playtest-приложения только эта ветка.
- Секреты `STEAM_USER` / `STEAM_PASS` — тот самый отдельный аккаунт с правом *Publish to Playtest*.

### 3. Чек-лист перед первым прогоном
- [ ] `app_build_playtest.vdf` указывает на **Playtest Depot ID**.
- [ ] В Steamworks → Playtest → **Builds** видно «No builds yet».
- [ ] CI заливают в `playtest` ветку, а не в `public`/`beta`.
- [ ] Лимит 200 человек настраивается в Steamworks → Playtest → **Manage Playtest** → *Max users*, **не** в VDF.

### 4. Типичная ошибка
> `ERROR! Depot 1234571: Failed to add file ...`  
> Причина: `FileMapping` в VDF смотрит в `../export/playtest/`, а экспортёр кладёт в `../export/playtest/windows/`.  
> **Фикс:** либо `export_path: ../export/playtest/` + `LocalPath "*"` (как выше), либо `LocalPath "windows/*" DepotPath "."`.

---

**Итог:** копируешь джоб, меняешь `appid`/`depotid`/VDF/ветку — всё. Никаких новых скриптов.
