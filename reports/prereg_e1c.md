## 3. Модель и условия

- **Тестируемая модель:** `nvidia/nemotron-3-ultra-550b-a55b` через API NVIDIA (бесплатно), температура 0, **рассуждения выключены во всех вариантах**.
- **Кэш и обрывы:**
  - каждый вызов кэшируется на диске; повторный запуск продолжает с места остановки без новых запросов;
  - жёсткий предел 240 с на вызов, повторы при 429 и 5xx.
- **Лимиты:** контекст 6600 токенов, ответ ≤ 1500, блок памяти ≤ 600, резюме ≤ 500, окно истории 3750.
  - Токены для лимита считаются токенизатором Qwen2.5 как приближением — одинаково для всех вариантов.
- **Сжатие и порядок:** как в E1b — резюме пишет та же модель, вопросы по порядку, follow-up в истории, у каждого варианта своя копия чата.

  - приёмка на ручной разметке Егора всех 10 рёбер: раунд 1 — 6/10 (оценивалась и понятность X), раунд 2 — **9/10** (интервал Уилсона 0,60–0,98);

## 5. Метрики (на ответ)

- **вывод (главная)** — строгая рубрика **e1c.2**:
  - сначала судья проверяет обязательное условие типа вопроса и пишет проверку отдельной строкой (поле `mandatory`); если условие не выполнено, вывода нет:
    - «менялось» — отвергнутый или заменённый вариант не предлагается ни как текущий, ни как опция;
    - «уточнить» — названа развилка или задан явный вопрос;
    - «связать» — опора на связующие факты;
  - затем вывод засчитывается только при всех ключевых элементах эталона;
- опора, неуместный совет, устаревшее, постороннее — тот же судья;
- **вывод (мягкий)** — рубрика e1b.3, вторичная метрика (§7);
- **выдумка** — ручная слепая проверка всех ответов, отмеченных хоть одним судьёй, отдельной сессией Claude с диалогом загрузки (правило E1b v1.3);
- удержание — по парам follow-up → вопрос.

**Метрики выбора (V7)** — без автоматического судьи (решение Егора: живая проверка gpt-oss ошибалась примерно на трети пунктов):
- доля вопросов, где модель что-то выбрала; доля «НИЧЕГО»; доля нарушений формата и номеров вне меню — считаются автоматически;
- **уместность выбранного — ручная проверка Егора:**
  - 40 случайных выборов V7 на новых проектах (seed 0, `scripts/e1c_selection_sample.py`): вопрос, меню, как его видела модель, ответ на шаге выбора, раскрытое;
  - для каждого пункта — «относится» 1/0, в целом — «упущено важное».

Все метрики считаются отдельно по типам вопросов и по проектам.

## 6. Гипотезы и тесты

**H-выбор (основная, решение Егора):** V7 лучше V6 по «выводу» (e1c.2) на 200 новых вопросах.
- Точный McNemar по вопросам, двусторонний, α = 0,05, один тест.
- Подтверждена, если p < 0,05 и разница в пользу V7.
- **Защита:** V7 не хуже V6 по «выдумке» — верхняя граница 95 % бутстреп-интервала разницы ≤ +5 п.п.

**Вторично (описательно, с 95 % интервалами; тесты — без поправок, как исследовательские):**
- V7 против V2, V7 против V1, V6 против V2;
- разрезы по типам («менялось», «связать», «уточнить», «вспомнить»);
- «вывод (мягкий)»;
- слой из 54 старых вопросов (судья gpt-oss);
- метрики выбора и ручная проверка 40 выборов.

**Мощность** (по разбросу E1b, доля разногласий 0,17–0,25; 200 вопросов, α = 0,05, один тест): для +10 п.п. 0,78–0,93. Неотвергнутая гипотеза значит «не показано», а не «нет эффекта».

## 11. Поправка v1.1 (Егор, 2026-10-26) — мягкая рубрика на 20 %

1. **Причина — скорость NVIDIA.** gpt-oss-20b за ≈ 1 ч оценил ≈ 20 ответов на задачу; мягкая рубрика на всех 1016 ответах заняла бы несколько суток.
2. **Решение:** «вывод (мягкий)» (рубрика e1b.3, gpt-oss) считается только на той же детерминированной выборке 20 %, что и κ: sha256 ключа «проект|вопрос|вариант», `--sample 0.2`, 4 новых проекта. Уже полученные мягкие вердикты вне выборки в анализ не входят.
3. **κ и старый слой** (54 вопроса × 4, gpt-oss, e1c.2) — по плану, целиком.
4. **Когда принята:** после того, как посчитан и показан главный тест (V7 против V6 по «выводу», судья DeepSeek). Поправка касается только вторичной описательной метрики; главный тест, защита по «выдумке» и остальное — без изменений.
