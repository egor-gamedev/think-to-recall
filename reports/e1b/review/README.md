# Слепая проверка «выдумки», E1b

Файл для работы: `fabrication_review.csv`, 145 ответов ассистента о проектах пользователя. Вариант памяти и источник ответа скрыты (id — хэш), порядок перемешан.

Для каждой строки:
1. Открой `facts_<project>.md` — там все факты проекта (устаревшие помечены «УСТАРЕЛО») и текст вопроса по id.
2. Прочитай `answer`.
3. Колонки `judge1_fabricated` и `judge2_fabricated` — что заподозрили автоматические судьи. Это подсказка, а не ответ: судьи часто записывают в выдумку обычные неуместные советы.

**Правило (пре-регистрация E1b, §7).** Выдумка = 1, только если ответ **утверждает как факт о проекте пользователя**, что в проекте **уже есть, решено или действует X**, а X нет среди фактов и в вопросе или X противоречит фактам. Например: «у вас уже есть таблица users с паролями», «раз вы используете PostgreSQL…», если в проекте этого нет.

**Выдумка = 0:**
- предложения, советы, планы, примеры кода — даже неуместные («можно добавить логин по паролю», «установите solana-web3.js»);
- опора на УСТАРЕВШИЙ факт — это отдельная метрика, не выдумка;
- общие утверждения о мире, не о проекте.

**Что заполнить:** `fabrication(0/1)` — 0 или 1; `reviewer` — `Claude, отдельная сессия`; `note` — при 1 короткая цитата утверждения, при спорном 0 — пара слов почему.
