## 2. Литература: есть ли уже такая схема

Схема: меню из **извлечённых** подсказок + выбор моделью + рекурсия + сокращения по контексту + закрепление по пользе.

**Ответ: частично.** Каждая часть есть отдельно, вместе — не нашёл. Читал аннотации и, где удалось, раздел метода; поиск не исчерпывающий.

| Работа | Что совпадает | Чего нет |
|---|---|---|
| MRAgent, arXiv 2606.06036 (страницы и ICLR 2026, и ICML 2026 — площадку уточнить) | граф Cue–Tag–Content из своей истории; LLM на каждом шаге выбирает переходы и отсекает | граф строит **LLM** при записи; граф статичен — нет закрепления, сокращений, внешних графов |
| Think-on-Graph (2307.07697) / ToG-2 (2407.10805, ICLR 2025) | LLM выбирает соседей, beam search, лимит глубины | внешний KG, цель — ответ на вопрос; без обучения графа |
| HippoRAG 2 (2502.14802, ICML 2025) | граф из текста, ассоциативное расширение | расширяет алгоритм (PPR), не модель |
| A-MEM (2502.12110, NeurIPS 2025) | заметки-связи, память эволюционирует | связи и обновления пишет LLM |

| **Kairos**, «Validation-Gated Hebbian Learning» (NeurIPS 2025 workshop) — новое | закрепление **только после проверки качества** — ближе всего к «по пользе» | маленький proof-of-concept, мультиагентное рассуждение |
| Обзор графовой памяти, 2602.05665 | таксономия: извлечение, хранение, поиск, эволюция | — |
| arXiv 2603.19087 — **настоящее название** «Assessing the Effect of Cross-Domain Mapping on Creativity in Humans and LLMs» (Liu, Griffiths и др.) | подтверждает концепцию: LLM в среднем не выигрывают от подсказок; помогают только далёкие и только сильным моделям | — |

Не нашёл ни у кого: (а) подсказки из **публичных графов** (WordNet / Викиданные / ConceptNet) как меню к собственному контексту модели; (б) сокращения пути, **привязанные к контексту**; (в) закрепление по попаданию в ответ вместе с квотой на далёкое. Это и есть заявка на новизну — но слабая по отдельности: (в) близко к Kairos, выбор моделью — к MRAgent/ToG.

## 3. Модель (проверено 2026-10-18, 3 запроса на каждое имя)

Решение Егора: **DeepSeek V4.1 Flash** через timeweb (`https://api.timeweb.ai/v1`).
- В каталоге timeweb нет имени с «4.1». Есть `deepseek/deepseek-flash` и `deepseek/deepseek-v4-flash`; у обоих одинаковый `system_fingerprint` `e72d3c7f…`, то есть за двумя именами одна модель.
- Внешние источники (не официальная документация DeepSeek): `deepseek-flash` — официальное имя V4.1 Flash, а `deepseek-v4-flash` временно перенаправляется на V4.1. **Беру `deepseek/deepseek-flash`.** Что это именно V4.1, подтверждено только косвенно.
- Вызов инструментов работает: модель вызвала `expand({"node_id": "n_fish"})`.
- Контекст 1 000 000 токенов на вход, до 393 216 на выход (метаданные `/models`).
- **Thinking включён по умолчанию**: при `max_tokens=50` все 50 токенов ушли на рассуждение, `content` пустой. Для E1 нужно либо выключить thinking (проверить, принимает ли timeweb такой параметр), либо давать запас `max_tokens` и считать токены рассуждения в расходе. Решить в пре-регистрации.
- Кэш промпта отображается в usage (`prompt_cache_hit_tokens`).
- Цены timeweb не проверял.

## 4. Риски, замеченные на разведке

1. Задачи E1 (бэкенд, требования из файлов проекта) плохо ложатся на WordNet / ConceptNet: скрытые требования там — «офлайн 4 дня», «общие планшеты», а не таксономия. Скорее всего полезным окажется слой «собственный опыт» и сущности из контекста, а публичные графы дадут шум. Это стоит проверить первым на этапе 1 (5 задач widethink → посмотреть меню глазами) до разметки 100 рёбер.
2. Судья: в задании — nemotron через NVIDIA, в widethink — deepseek-v4-pro. Судья не должен быть DeepSeek, раз тестируем DeepSeek Flash.
