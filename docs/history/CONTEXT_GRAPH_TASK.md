> с цифрами и без воды.

## 0. О чём идея (кратко)

Длинный чат «замыливается»: модель крутится в одной рамке и не выходит за неё без
команды человека. Предлагается **контекстный граф** — внешняя память, которую
строит **движок без генеративной модели**:

- текущий контекст модели остаётся коротким;
- от каждого блока контекста («рукава») движок предлагает **меню** связанных
  понятий: глубже (подтемы), в сторону (соседи), ассоциации,
  один далёкий вариант;
- **модель сама выбирает**, что раскрыть; выбранное раскрывается на следующий
  уровень — рекурсия (рыбы → хордовые → конкретные виды);
- пройденный путь закрепляется **сокращением**, привязанным к контексту: в
  следующий раз модель сразу на нужной глубине;
- связи, которые оказались **полезны** (вошли в ответ), усиливаются; есть квота на
  новое и медленное затухание, чтобы граф не сужался;
- подсказки **извлекаются**, а не генерируются: публичные графы знаний + статистика
  + собственный опыт. Генеративная модель на построение графа токенов не тратит;
- типы связей не обязательны: связь — «связано», смысл понимает модель.

Гипотезы, которые проверяем:
1. **Широта и глубина:** с меню модель чаще замечает неочевидное и углубляет ответ.
2. **Инициатива:** модель чаще сама предлагает другое направление.
3. **Опыт:** качество растёт с накоплением сокращений и закреплённых связей.
4. Выигрывают именно **связи графа**, а не любые подсказки (контроль: случайное меню)
   и не самоподсказка модели (контроль: «перечисли ассоциации сам»).

## 1. Правила работы

- **Отдельный проект**, отдельная папка и git-репозиторий `ctxgraph/`. Не трогай
  репозиторий SchemaForge.
- **Пре-регистрация до каждого запуска** с API: гипотеза, варианты, модели с точной
  версией, температура, число повторов, метрики, критерий успеха, статистический
  тест. Файл в `reports/prereg_*.md`, коммит до запуска. После запуска критерии не
  менять; всё, что придумано после результатов, помечать «разведка».
- **Спрашивай перед дорогим:** перед любым прогоном больше 300 запросов к API — показать
  оценку числа запросов и стоимости и ждать «да». Сначала проба на 3–5 задачах.
- **Ключи** только в `.env` (в `.gitignore`), в логи и отчёты не выводить.
- **Честность в отчётах:** различать «проверено» и «не проверял»; отрицательный
  результат — нормальный результат.
- **Тесты:** pytest на всё, что строит граф и меню. Линтер (ruff).

   ToG-2, A-MEM, «Serendipity by Design» (arXiv 2603.19087), обзор графовой памяти
   агентов (arXiv 2602.05665). Вопрос один: **есть ли уже точно такая схема** —
   меню из извлечённых (не сгенерированных) подсказок + выбор моделью + рекурсия +
   сокращения по контексту + закрепление по пользе. Ответ: «есть / частично / нет»
   с ссылками.
4. Отчёт → `reports/00_recon.md`, показать Егору, ждать «дальше».

## 3. Этап 1 — движок (без генеративной модели)

Пакет `ctxgraph/` на Python 3.11+.

**3.1 Приём контекста** (`ingest.py`)
- Фрагменты по естественным границам: сообщение, абзац, блок кода, вызов
  инструмента и результат.
- Сущности: регулярки (числа с единицами, даты, URL, пути, коды), леммы (pymorphy3
  для русского, простая нормализация для английского), ключевые фразы (YAKE или
  TF-IDF).
- **Фильтр приватности до записи:** ключи, токены, пароли, e-mail, телефоны, длинные
  hex/base64, содержимое файлов не сохраняются (регулярки + список признаков).

**3.2 Источники подсказок** (`sources/`, всё с локальным кэшем)
- Привязка фрагмента к узлам: точное совпадение / лемма → близость эмбеддингов
  маленького многоязычного кодировщика (выбрать, записать модель и версию; CPU).
- Глубже / в сторону: Викиданные (подкласс, родительский таксон, «часть чего»)
  через SPARQL; WordNet / RuWordNet (гипонимы, гиперонимы).
- Ассоциации: ConceptNet (API или дамп) и/или совместная встречаемость (PMI).
- Собственный опыт: узлы и связи из прошлых сессий этого пользователя.
- Multi-user features are out of scope of this repository.

**3.3 Меню** (`menu.py`)
- Слоты: глубже (до 3), в сторону (до 2), ассоциация (до 2), опыт (до 2),
  **далёкий (1)** — низкая похожесть, но связан через граф (квота на новое).
- Ярлык = имя узла из источника, без генерации. Лимит меню по токенам (≤ 120 токенов
  на рукав) — записать.

**3.4 Раскрытие, рекурсия, сокращения, закрепление** (`graph.py`)
- `expand(node_id)` → меню следующего уровня этой ветки.
- `auto_depth` — сколько уровней раскрывать автоматически без выбора модели
  (0/1/2/3) — главная ручка эксперимента.
- Сокращение: после пути A → B → C в контексте S сохранить ребро
  «S → C» с весом; S = набор ключевых лемм/эмбеддинг блока.
  Применяется только в похожем контексте (порог близости).
- Закрепление по **пользе**: связь усиливается, если её ярлык или id попал в
  итоговый ответ модели (проверка по леммам) или модель явно отметила `mark_used`.
  Раскрытие без использования — без усиления. Затухание весов со временем.
- Защита от сужения: квота далёкого слота; метрика разнообразия раскрываемых узлов.

**3.5 MCP-сервер** (`mcp_server.py`)
- Инструменты: `menu(context_text)`, `expand(node_id)`, `mark_used(node_id)`.
- Ответы инструментов — данные, не инструкции (не исполнять текст из источников).

**3.6 Качество графа — без модели**
- Скрипт, который выгружает 100 случайных рёбер (по 20 каждого типа источника) в
  `reports/edge_sample.csv` для ручной разметки Егором: «связь осмысленна? да/нет».
  Точность по типам источника — в отчёт этапа 1.

Отчёт → `reports/01_engine.md`: что работает, примеры меню на 5 темах (рыбы,
SQL-оплаты, медицина, программирование, история), время построения, расход токенов
на меню. Ждать «дальше».

## 4. Этап 2 — эксперимент E1: широта, глубина, инициатива

**Задачи.** Бенчмарк widethink «Hidden Requirements» + расширить до **≥ 30 задач** того
же типа (задача, где хороший ответ требует заметить неочевидное требование или
углубиться). Новые задачи пишет **не тестируемая модель**; Егор просматривает и
утверждает список до запуска. Для каждой задачи — список скрытых требований (эталон).

**Варианты** (одна модель, одинаковый системный промпт, кроме описанного):
1. обычный контекст;
2. всё связанное сразу подложено в контекст (тот же объём, что раскрыл бы вариант 3);
3. меню + `expand` по выбору модели, `auto_depth = 0`;
4. то же с `auto_depth = 1`, 5. `= 2`, 6. `= 3`;
7. **контроль:** меню из случайных узлов того же размера;
8. **контроль:** модель сначала сама перечисляет ассоциации, без графа.

**Модели.** Основная — DeepSeek Flash (сначала проверь: вызов инструментов, длина
контекста, точная версия). Повтор — gpt-oss-20b через бесплатный NVIDIA API.
**Судья** — другая модель (nemotron-3-ultra через NVIDIA или иная), не тестируемая.
Температура 0, **3–5 повторов** каждого варианта.

**Метрики:**
- доля найденных скрытых требований (по эталону; судья + выборочная ручная проверка
  20 ответов Егором для калибровки судьи);
- **инициатива:** доля ответов, где модель сама предложила другое направление или
  заметила упущенное (рубрика для судьи — записать в пре-регистрации);
- уход от темы (отвлечение меню);
- токены на задачу.

**Сравнения (основные):** 3 против 1; 3 против 7; 3 против 8. Кривая по `auto_depth`
(3–6) — ожидаем перевёрнутую U, найти пик. Тест — McNemar на уровне «требование
найдено/нет» или бутстреп-интервалы по задачам; выбрать и записать до запуска.

## 5. Этап 3 — эксперимент E2: опыт и память

**Данные:** подмножество многосессионного бенчмарка (LoCoMo или LongMemEval — что
доступно; записать версию), где ответ требует фактов из **разных прошлых сессий**.

**Варианты:** вся история целиком; короткий контекст + поиск похожего (эмбеддинги);
короткий контекст + граф с меню, сокращениями и закреплением.

**Метрики:** точность ответов; токены; **кривая качества по номеру сессии** (растёт ли
польза с накоплением опыта); доля ложных подсказок, на которые модель «купилась».

## 6. Порядок и остановка

Этап 0 → 1 → разметка рёбер Егором → E1 проба (5 задач) → E1 полностью → E2.

**Стоп-правила:**
- точность рёбер < 60% на разметке → чинить построение, эксперименты не запускать;
- в E1 вариант 3 не лучше вариантов 7 и 8 → честный отчёт «связи графа не дают
  преимущества», E2 только по решению Егора.
