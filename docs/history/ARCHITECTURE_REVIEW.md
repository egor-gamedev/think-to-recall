## 1. Отчёт «как устроено сейчас» (`reports/arch_00_current.md`, только чтение кода)

## 2. Предложение архитектуры v2 (`ARCHITECTURE_V2.md`)

Принцип Егора: **разбить на части; где часть уже исследована и наша не отличается — взять
готовое решение профессионалов, а не изобретать.** Своё — только то, чего нет.

| часть | готовое решение (проверить, описать, выбрать) |
|---|---|
| 1. Приём | эпизоды с провенансом (Graphiti): каждая реплика — эпизод, всё извлечённое ссылается на эпизод |
| 2. Извлечение без генеративной модели | GLiNER (мультиязычная версия) — сущности; GLiREL / GLiNER-Relex — связи. **Проверить на русском** на 30 репликах наших проектов. Запасной вариант — нетипизированные связи «встречаются в одном предложении» (типы не обязательны — решение Егора) |
| 3. Структура | как HippoRAG 2: узлы-понятия + узлы-фрагменты (предложение / реплика) + рёбра «содержит» + рёбра синонимов (близость эмбеддингов выше порога) + рёбра связей |
| 4. Обновление | **инкрементально, никогда не перестраивать целиком** (LightRAG: слияние множеств узлов и рёбер; Graphiti: у связей время начала и конца, при смене решения старая связь **помечается недействительной**, а не удаляется). Хранение — SQLite или аналог, без перезаписи файла |
| 5. Поиск стартовых узлов | гибрид dense + BM25 + RRF (оставить) |
| 6. Распространение | персонализированный PageRank от стартовых узлов (HippoRAG 2) вместо «1 шаг + бонус пересечений» |
| 7. Отбор в память | cross-encoder (например, bge-reranker-v2-m3), единица — предложение |
| 8. **Рукава мышления (своё)** | рукав = группа токенов шага (2–6 слов, одна тема) → стартовые узлы → **мини-граф рукава** (PPR от его стартов: узлы, фрагменты, веса). Пересечение рукавов = узлы с весом в ≥ 2 мини-графах. Периферия ≤ 20 %, вес по глубине, якорь цели, пометка «необязательно» |
| 9. **Закрепление и сокращения (своё)** | описать интерфейс, не реализовывать |

Для каждой части: что берём (статья / библиотека, версия, лицензия), как адаптируем, чем
отличается наше, риски. Отдельно: учесть вывод HippoRAG 2 — подход «только сущности» теряет
контекст; поэтому фрагменты текста — полноправные узлы. Не начинать реализацию до «да» Егора.

## 2а. Дополнения Егора (архитектура v2 утверждена с ними)

**Принцип: заимствовать по максимуму.** Для каждой части сначала искать готовое проверенное
решение (статья, библиотека, бенчмарк, метрика). Своё — только где готового нет или оно
противоречит идее. В `ARCHITECTURE_V2.md` у каждой части графа «откуда взято».

**Язык.** Внутреннее представление и вся работа — на английском (брифы, код, метки, отчёты
подсессий; отчёты Егору — на русском). Вход пользователей может быть на любом языке:
- эмбеддинги и переранжирование — мультиязычные (записать модели);
- узлы-понятия по возможности привязывать к **Wikidata QID** — язык-независимый id, метка на
  английском; узлы без привязки — английская метка + исходная форма.

**Межсессионность.** Граф пользователя живёт между сессиями (эпизоды с id сессии и временем),
инкрементально, без перестройки.

**Обезличивание до записи:** готовые инструменты (например, Microsoft Presidio + наш фильтр
ключей/секретов); проверить на русском и английском. Multi-user features are out of scope of this repository.

**Тесты.** Только маленькие, **≤ 5 минут** на прогон, для отладки и проверки, что часть
работает. Правило: маленькие тесты — для разработки, не для выводов. Выводы — только на
**чужих** бенчмарках, одним прогоном с замороженной конфигурацией и пре-регистрацией.

**Бенчмарки — чужие.** Наши E1b/E1c — только набор для отладки. Подобрать и описать готовые
(с официальными метриками и, где есть, судьями), сопоставив с нашими типами:
- LongMemEval (multi-session ≈ «связать», knowledge-update ≈ «менялось», abstention ≈
  «уточнить»);
- LoCoMo;
- MemoryAgentBench (если подходит: есть проверка разрешения противоречий);
- многошаговые: MuSiQue / 2WikiMultiHopQA (на них мерили HippoRAG 2 — прямое сравнение).
Для каждого: размер, лицензия, сколько вызовов API на полный прогон и на подвыборку, чьи
опубликованные цифры можно взять для сравнения.

## 3. Демо графа (после «да» по архитектуре)

Цель: Егор **видит**, что хранится, как связывается и как модель это использует.

- Локальная веб-страница (один HTML, например Cytoscape.js или vis-network), данные — из
  графа одного проекта (crypto-wallet).
- **Вид «граф»:** узлы-понятия и узлы-фрагменты разными формами; рёбра по типам; у каждого узла
  — откуда взят (эпизод, текст), когда; недействительные связи — пунктиром с датой.
- **Вид «по времени»:** ползунок по номеру реплики — граф растёт инкрементально; видно, что
  ничего не пересоздаётся, а при смене решения старая связь гаснет.
- **Вид «вопрос»:** ввести вопрос → стартовые узлы → рукава (текст, из которого получены) →
  мини-граф каждого рукава с весами → пересечения → что ушло в память модели (текст блока
  целиком) → по желанию ответ модели (бесплатная NVIDIA, по кнопке).
- **Фильтр приватности:** показать, что было отброшено при записи (без самих секретов — только
  тип и место).
- Скриншоты и короткая инструкция запуска в `reports/arch_demo.md`.
