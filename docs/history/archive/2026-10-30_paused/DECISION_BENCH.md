# Бенчмарк «Помнит решения» (E3) — для Claude Code, проект `ctxgraph/`

> Цель: измерить то, что пользователь чувствует сам — **повторяет ли ассистент то, от чего
> пользователь уже отказался**, после сжатия контекста и через много сессий. Результат должен
> читаться без объяснений («в N раз реже предлагает отвергнутое») и годиться для README,
> демо-видео и разговора с инвестором.
> Правила проекта прежние: пре-регистрация, спрашивать перед >300 вызовами API, ключи в `.env`,
> отчёты Егору на русском.
> Запускать **после** этапа B (V9), когда известен лучший вариант памяти. Сейчас — только
> подготовка данных (п. 1–3) и оценка стоимости.

## 1. Что измеряем

**Боль:** ассистент после сжатия / на следующий день снова предлагает отвергнутое
(«возьмите Postgres», хотя перешли на SQLite) или забывает, почему от чего-то отказались.

**Главная метрика — «повтор отвергнутого»:** доля пробных вопросов, где ответ **рекомендует**
вариант, от которого пользователь отказался (меньше — лучше). Упоминание с оговоркой
(«Redis вы отклонили из-за X, поэтому…») повтором не считается.

**Обязательная защита — «ложный запрет»:** на контрольных вопросах (где ничего не отвергалось)
ответ не должен выдумывать отказ («вы же отказались от X») или отказываться от разумного
варианта. Без этой метрики «никогда ничего не советовать» выглядело бы победой.

Вторичные: «учёл актуальное» (назвал то, на что заменили), «помнит причину» отказа,
«выдумка» о проекте, токены и задержка на ответ, **вызовы LLM на построение памяти**
(у ctxgraph — 0, у Mem0 / Zep — по каждому сообщению).

## 2. Данные

- **Проекты:** 4 проекта E1c (загрузка уже есть) + 2 новых других жанров (например, личный
  финансовый план, ремонт квартиры) — чтобы не было только про программирование.
- **События отказа** в загрузке, ≥ 15 на проект, каждое с id и временем:
  - **отказ:** «X не берём, потому что …»;
  - **замена:** «был A, переходим на B, потому что …»;
  - **условный отказ:** «X нельзя для Y, но для Z можно» — ловит перегиб в обратную сторону;
  - **возврат:** отказались от X, позже вернулись к X — актуально последнее.
  Существующие загрузки дополнить вставками, не переписывая; новые сцены генерирует **не
  тестируемая** модель, Егор просматривает выборочно.
- **Пробные вопросы**, ≥ 40 на проект:
  - **ловушка** (~50 %): обычный вопрос, на который шаблонный ответ — как раз отвергнутый
    вариант («как хранить сессии?» при отвергнутом Redis). В вопросе отказ **не упоминается**;
  - **условный** (~15 %): допустимый случай условного отказа (вариант можно);
  - **возврат** (~10 %);
  - **контроль** (~25 %): тема без отказов — для «ложного запрета».
  У каждого: id события, отвергнутый вариант и его формы написания, ожидаемое поведение.
- **Время:** каждый вопрос задаётся после 1, 3 и 5 сжатий (кривая забывания).

## 3. Оценка

- «Повтор отвергнутого» — узкий вопрос судье: «рекомендует ли ответ вариант X как решение?
  да / нет / упоминает с оговоркой». Узкий вопрос ⇒ ожидаем высокое согласие судей.
  Предварительный фильтр без судьи: если X (по формам написания) вообще не встречается — «нет».
- Второй судья на 20 %, κ в отчёт; **ручная проверка Егором 50 случаев** до основного вывода.
- Судья — не та модель, что отвечает.

## 4. Варианты

1. без памяти (только сжатие);
2. **«умное резюме»:** промпт сжатия явно требует вести список решений и отказов — так
   работает встроенная память многих ассистентов; это честный и сильный соперник;
3. простой RAG (V2);
4. сильный RAG (V2+: гибрид + предложения + переранжирование);
5. лучший вариант ctxgraph по итогам этапа B;
6. **Mem0** (open source) — после оценки стоимости и «да» Егора;
7. (позже) Zep / Graphiti.

Отвечающие модели — **две**: средняя и сильная (результат не должен держаться на одной).

## 5. Критерии (в пре-регистрацию)

- **Успех для заголовка:** ctxgraph снижает «повтор отвергнутого» относительно варианта 1 не
  менее чем вдвое **и** относительно лучшего из вариантов 2–4 не менее чем на 25 %
  (относительно), McNemar с поправкой Холма; «ложный запрет» не выше более чем на 3 п.п.
- **Успех по цене:** качество не хуже Mem0 (граница −5 п.п.) при 0 вызовов LLM на построение.
- Если ни то ни другое — честный отчёт; заголовков не делаем.

## 6. Что выдать кроме отчёта

- **Таблица для README:** повтор отвергнутого, ложный запрет, вызовы LLM на построение,
  задержка — по вариантам, с интервалами.
- **3 случая для демо-видео:** один и тот же вопрос, ответ без памяти и с ctxgraph, текст
  целиком, отобранные **до** просмотра общего результата по заранее заданному правилу
  (например, первые три ловушки проекта crypto-wallet после 3 сжатий) — чтобы не было
  подбора лучших примеров.
- **Скрипт воспроизведения** одной командой — чтобы любой мог проверить цифры.

## 7. Порядок

1. Дополнить один проект событиями отказа + 40 вопросов → показать Егору.
2. Оценка числа вызовов и стоимости для всех вариантов, включая Mem0 → «да» Егора.
3. Проба: 1 проект × все варианты × 10 вопросов; проверить судью на 50 случаях.
4. Пре-регистрация → полный прогон → отчёт `result_e3.md`.
